pg_tokenizer 1.1.0 improves definition-cache consistency, text-analysis correctness, and configuration privileges for PostgreSQL 14–18.

[English release notes](https://vchord.pgsty.com/blog/release/pg-tokenizer-1.1.0/) · [Chinese release notes](https://vchord.pgsty.com/zh/blog/release/pg-tokenizer-1.1.0/) · [Installation guide](https://github.com/pgsty/pg_tokenizer/blob/v1.1.0/docs/01-installation.md) · [Full changelog](https://github.com/pgsty/pg_tokenizer/compare/v1.0.0...v1.1.0)

## Release scope

This release is accepted for **fresh installations**. Upgrade compatibility, per-schema default-privilege migration, snapshots spanning an upgrade, and staging manifests left by failed build preflight are outside this release's acceptance scope. Existing migration scripts remain in the source tree for separate evaluation.

## Highlights

- **Replicated definition invalidation.** Analyzer, tokenizer, model, stopword, and synonym caches use a transactional catalog version that is replicated through WAL. Lookups respect the caller's SQL snapshot on the primary, on a standby, and after promotion.
- **Prepared transaction cleanup.** `PREPARE TRANSACTION` clears local derived objects and validation state. Direct catalog DML followed by `ROLLBACK PREPARED` cannot leave an aborted configuration cached when a later transaction reuses its version number. Read-only transactions can still be prepared; definition-changing APIs continue to reject PREPARE.
- **Schema and privilege boundaries.** Runtime vocabulary tables and sequences live in `tokenizer_data`. Database owners can manage their vocabularies without CREATE privileges on `tokenizer_catalog`. Catalog-writing functions are marked `PARALLEL UNSAFE`; read-only analysis remains `PARALLEL SAFE`.
- **PostgreSQL dictionaries.** New `pg_dict` definitions bind schema-qualified dictionary names. Dictionary resolution no longer depends on the search path of a later caller.
- **Server-file permissions.** Lindera dictionary and user-dictionary files can be loaded only by superusers or roles with `pg_read_server_files` privileges. Matching models that are already loaded or preloaded remain reusable.
- **Text and vocabulary correctness.** Long custom tokens split at UTF-8 boundaries; repeated lexemes are aggregated before `tsvector` conversion; custom-model triggers honor target-column assignment semantics; Jieba `full` and `precise` modes now select the intended algorithms.
- **Analysis limits and cancellation checks.** Configurable budgets reject oversized input and output with SQLSTATE `54000`. Interrupt checks cover extension-owned analysis loops.
- **Installation and source packaging.** Manual installation examples replace the shared library without truncating a file mapped by PostgreSQL. The source ZIP includes a Makefile, validated metadata, locked dependencies, and SQL files for PGXN-compatible builds.

`tokenize(text, tokenizer_name)` continues to return `INT[]`. `analyze_to_tsvector` and `tokenize_to_tsvector` continue to return native PostgreSQL `tsvector` values. Neither `vchord` nor `vchord_bm25` is required to use pg_tokenizer.

## Packages and installation

The release contains `.deb` and `.zip` packages for PostgreSQL 14, 15, 16, 17, and 18 on x86_64/amd64 and aarch64/arm64. These GitHub binaries are built on **Ubuntu 24.04** with `lindera-ipadic`, which embeds IPADIC. Use a package matching the operating system, PostgreSQL major version, and architecture. For other distributions, use a matching native package from the Pigsty repository or build from source.

`pg_tokenizer-1.1.0.zip` is the source distribution. Its `.sha256` file verifies that archive; `SHA256SUMS` covers the binary packages and source ZIP. Preparing a PGXN-compatible archive does not publish it to PGXN.

After installing the package, add `pg_tokenizer.so` to `shared_preload_libraries`, preserving any other required libraries, and restart PostgreSQL. Then create the extension in the target database:

```sql
CREATE EXTENSION IF NOT EXISTS pg_tokenizer;
SET search_path TO "$user", public, tokenizer_catalog;

SELECT create_text_analyzer(
    'words',
    'character_filters = ["to_lowercase"]
pre_tokenizer = "unicode_segmentation"'
);
SELECT apply_text_analyzer('Hello World', 'words');
-- {hello,world}
```

The extension library must be preloaded before the server starts. Installing a replacement library does not reload an already running PostgreSQL server.

## Validation

The release workflow requires a successful Check run for the tagged commit on PostgreSQL 14–18 and both Linux architectures. Each release build installs its generated DEB, compares the installed files with the matching ZIP, and runs the SQLLogicTest, integration, preload, and physical-standby suites against the packaged library.

The prepared-transaction regression was also verified on macOS arm64/PostgreSQL 18.6: it failed against the unpatched baseline and passed after the cache fix, including the version-reuse case and `COMMIT PREPARED`.

## Limits and compatibility notes

- Analysis budgets do not impose a hard memory limit or a bounded cancellation latency inside third-party libraries. Load trusted model configurations and bound documents in the application. [Issue #13](https://github.com/pgsty/pg_tokenizer/issues/13) remains open for this limitation.
- Direct catalog DML still bypasses API configuration validation and remains an administrative operation.
- Queries on a standby can retain older definitions until the relevant WAL has replayed and the query takes a new snapshot.
- Jieba's `full` and `precise` modes were swapped in 1.0.0 and earlier. If reusing persisted output produced with either mode, regenerate it and rebuild dependent indexes. The default `search` mode is unchanged.
- External Lindera dictionaries must be compiled with Lindera 6. Native Pigsty RPM/DEB packages do not embed dictionaries; their packaging differs from these GitHub artifacts.

See the [limitations](https://github.com/pgsty/pg_tokenizer/blob/v1.1.0/docs/07-limitation.md) for analysis budgets, snapshots, privileges, and backup requirements.
