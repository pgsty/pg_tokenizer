pg_tokenizer 1.2.0 updates `pgrx` to `0.20.0` and supports **PostgreSQL 15–19** on **`x86_64` and `aarch64`**.

## Highlights

- **PostgreSQL 15–19 & pgrx 0.20.0**: Add PostgreSQL 19 support across source builds, CI, and release packages (`x86_64` and `aarch64`), requiring Rust 1.99.1+ and matching Clang/libclang/LLVM tools. PostgreSQL 14 is no longer supported upstream by `pgrx 0.20.0`.
- **Trigger exception cleanup**: Restore the caller memory context and guard process/transaction exit paths in `ExecutorState::drop` when custom-model target-column coercion fails (such as `varchar(n)` length errors or domain `CHECK`/`NOT NULL` violations).
- **Pre-release PostgreSQL version parsing**: Fix `tools/pgxn.py` major-version detection for pre-release `pg_config --version` strings such as `PostgreSQL 19rc1` and `PostgreSQL 19beta2`.
- **Install & CI verification**: Add automated checks for install SQL parity, exported C symbols across the full upgrade chain, and PostgreSQL server log health.

## Packages and Upgrading

- **Linux packages**: Prebuilt GitHub `.deb` and `.zip` packages are built on Ubuntu 24.04 with embedded `lindera-ipadic` (`glibc >= 2.39`, compatible with Ubuntu 24.04+ and Debian 13+). On older Linux distributions, install native packages from the [Pigsty repository](https://pigsty.io/ext/e/pg_tokenizer) or build from source.
- **In-place 1.1.0 → 1.2.0 upgrade**: Install the `1.2.0` shared library and SQL files on the primary and all replicas, restart PostgreSQL, and run `ALTER EXTENSION pg_tokenizer UPDATE;` in each database. All SQL APIs, catalog definitions, `tokenizer_data` custom vocabularies, and token IDs are preserved without re-tokenization. For upgrades from `1.0.0` or `0.1.x`, see the [installation guide](../01-installation.md#upgrading).
